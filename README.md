# open-inflation

The Open Base-Money Evidence Repository ([GildedPleb/open-inflation](https://github.com/GildedPleb/open-inflation)).

Simple time-series CSVs of global base money, where every observation is backed by a human-traversable, append-only Markdown evidence chain. Heavy artifacts stay external (archive.org); this repository holds only text.

Status: Waypoint 1, the skeleton and lint suite. There is no data yet.

## Layout

| Path                                       | What it is                                                                             |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| `base_money.csv`                           | `date,value,evidence_id`: quarter-end date, integer USD, path to the quarterly roll-up |
| `evidence/base_money/YYYYQn.md`            | Quarterly roll-up: summary table, component anchors, machine-readable arithmetic block |
| `issuers/<ISS>/<YYYY>.md`                  | Append-only extracts per issuer and year, one `## YYYYQn` heading per quarter          |
| `INDEX.md`                                 | Entry point; links every roll-up and issuer-year file                                  |
| `catalog.json`                             | Series metadata and file paths                                                         |
| `methodology/`                             | How the numbers are defined and built                                                  |
| `scripts/lint.ts`                          | All integrity checks                                                                   |
| `scripts/update.ts`, `scripts/backfill.ts` | Waypoint 3 and 4 entry points (not implemented yet)                                    |

## Run it

Requires Bun 1.4 and git ([Bun](https://bun.sh); lint reads the tree and its base commit through git, so work in a clone).

```sh
bun install
bun test          # offline unit tests with fixtures; about 1 second; the merge gate
bun run lint      # integrity checks on this repository
```

`bun run lint` compares the working tree with a base commit: `--base <ref>` if given; on a GitHub push to any branch but `main` (`GITHUB_EVENT_NAME=push`, `GITHUB_REF` not `refs/heads/main`), the merge-base of `HEAD` and `origin/main`, so a branch is linted against what it diverged from, not its own previous tip (lint exits 2 if that merge-base cannot be found); otherwise `$LINT_BASE` if set (CI passes the PR base on a pull request and `github.event.before` on a push to `main`; all zeros means no base), otherwise `HEAD`. Its only network use is for archive URLs that the diff adds, and only ones that pass L7: one HEAD request to the snapshot at `https://web.archive.org/web/<timestamp>/<url>`, and, if web.archive.org is unreachable, one request to `https://archive.org/wayback/available` to confirm that exact snapshot timestamp; and one HEAD request to each archive.today capture (`Archive URL 2`). At most 4 requests run at once, each with a 15 s timeout. Links already committed are never re-checked. Offline, lint exits 1 when the diff adds an archive URL; that is intended. `bun install` may use the network; `bun test` never does: tests that lint this repository lint a copy of its committed tree (never the working tree), and lint processes they spawn run with `OBM_NO_NETWORK` set, which makes lint refuse every request, so a new archive URL fails L8 as a network error. That variable can only take the network away; it never makes a URL pass. Research itself is not tested: `bun test` covers the software only.

Code checks: `bun run typecheck` and `bun run check` (format and code lint).

CI: `.github/workflows/lint.yml` runs all of the above on every push and pull request.

## Versions

Each series in `catalog.json` carries a semver `version` (base_money: `0.1.0` for the skeleton, `1.0.0` from its first published row, basket v1). The series' `baskets` list every basket of issuers ever used, versions 1..n, each with its coverage `floor_pct`; a committed basket entry is immutable as a whole (its issuers, their order and its `floor_pct`) and is never edited or removed. A basket change appends a new basket, with a major version bump plus a git tag. One CSV may hold rows computed under different baskets: each row keeps the basket in force when its quarter was first published, unless an appended Revision adds a newly evidenced issuer, which moves the row to the newer basket. The basket is recorded in the roll-up's machine block as `basket_version` (implied 1 while only one basket exists) and named per quarter in `INDEX.md`, which warns that rows on different baskets are not strictly comparable.
