# open-inflation

The Open Base-Money Evidence Repository ([GildedPleb/open-inflation](https://github.com/GildedPleb/open-inflation)).

Simple time-series CSVs of base money summed over a fixed basket of the largest central banks (the basket is listed in `catalog.json` and defined in `methodology/base_money.md`). It is not all global base money: each quarterly roll-up states the share of the basket it covers. Every observation is backed by a human-traversable, append-only Markdown evidence chain. Heavy artifacts stay external (archive.org and archive.today); this repository holds only text, and no source is ever self-hosted.

Status: dataset 1.0.0 (basket v1). The first row is 2026Q2; it excludes BCB, so it covers 98.79% of the basket (see the Coverage note in `INDEX.md`).

## Layout

| Path                                       | What it is                                                                             |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| `base_money.csv`                           | `date,value,evidence_id`: quarter-end date, integer USD, path to the quarterly roll-up |
| `evidence/base_money/YYYYQn.md`            | Quarterly roll-up: summary table, component anchors, machine-readable arithmetic block |
| `issuers/<ISS>/<YYYY>.md`                  | Append-only extracts per issuer and year, one `## YYYYQn` heading per quarter          |
| `INDEX.md`                                 | Entry point; links every roll-up and issuer-year file                                  |
| `catalog.json`                             | Series metadata and file paths                                                         |
| `methodology/`                             | How the numbers are defined and built                                                  |
| `scripts/lint.ts`                          | All integrity checks                                                                   |
| `scripts/update.ts`, `scripts/backfill.ts` | Waypoint 3 and 4 entry points (not implemented yet)                                    |

## Run it

Requires Bun 1.4 and git ([Bun](https://bun.sh); lint reads the tree and its base commit through git, so work in a clone).

```sh
bun install
bun test          # offline unit tests with fixtures; about 1 second; the merge gate
git fetch origin main
bun run lint --base origin/main   # integrity checks against main; no network (see AGENTS.md, Commands)
```

Local research scripts, never run in CI and never a merge gate:

```sh
bun run verify --base origin/main   # HEAD each archive URL the diff adds, once
bun run audit                       # re-check every link; copies go to ~/open-inflation-archive/
```

`bun run lint` compares the working tree with a base commit: `--base <ref>` if given; on a GitHub push to any branch but `main` (`GITHUB_EVENT_NAME=push`, `GITHUB_REF` not `refs/heads/main`), the merge-base of `HEAD` and `origin/main`, so a branch is linted against what it diverged from, not its own previous tip (lint exits 2 if that merge-base cannot be found); otherwise `$LINT_BASE` if set (CI passes the PR base on a pull request and `github.event.before` on a push to `main`; all zeros means no base), otherwise `HEAD`. Lint makes no network calls, ever, and neither does CI: L8 in lint checks the form of each archive URL offline, and neither lint nor CI ever contacts an archive or a source. `bun install` may use the network; `bun test` never does: a preload makes `fetch` throw in every test, and tests that lint this repository lint a copy of its committed tree (never the working tree). Research itself is not tested: `bun test` covers the software only.

`bun run verify [--base <ref>]` is a local research script, not a merge gate. It takes the same base as lint and is run while archiving new sources: it checks each newly added archive URL that passes L7 once, with one HEAD request to the snapshot at `https://web.archive.org/web/<timestamp>/<url>` (if web.archive.org is unreachable, a request to `https://archive.org/wayback/available` to confirm that exact snapshot timestamp, asked with the URL in up to three equivalent query forms, fully encoded, then with only `&`, `#` and `+` encoded, then that without the scheme, because the API caches each exact query string for hours and can replay an empty answer cached before the capture was indexed; the next form is asked only while the answer lists no snapshot or another one, and any answer other than the exact timestamp leaves the snapshot `unconfirmed`, no verdict), one HEAD request to each archive.today capture (`Archive URL 2`) and one GET to each Ghostarchive capture (`Archive URL 3`, at most the first 256 KiB of the page read), each with a 15 s timeout, and links already committed are never re-checked. An archive.today HTTP 403 or 429 is its CAPTCHA or rate limit: logged, no verdict, not a failure. It prints `archive.today: N verified, M unverified (R rate-limited, B blocked)` and the unverified URLs, sorted, for the researcher to open in a browser; M = R + B (+ U, shown as `, U unconfirmed` only when some URL had another no-verdict class). Each rate-limited or blocked line names the host and the HTTP status, e.g. `rate-limited (archive.ph HTTP 429; no verdict)`. A Ghostarchive HTTP 403 or 503 (its Cloudflare challenge) or 429 (its rate limit) is likewise no verdict, not a failure, summarized in the same shape, `ghostarchive: N verified, M unverified (R rate-limited, B blocked[, U unconfirmed])`, with the unverified URLs sorted. Ghostarchive answers HTTP 200 for its failed and unfinished captures too, so a 200 is verified only when the page is a capture (its `<replay-web-page>` player or `Archive date:` line); its `Archiving error` page is a finding (that URL will never hold a capture: record `attempted <YYYY-MM-DD>: <reason>` instead, and a Re-archive note does not excuse it), and any other 200 page (loading, in progress) is `unconfirmed`, no verdict. Requests are paced (verify and audit alike): one host's requests are serial and at least its interval apart (archive.today 30 s, Ghostarchive 5 s, web.archive.org 2 s, the archive.org availability API 5 s, any other host 1 s; override with `OBM_RATE_<HOST>_MS`, e.g. `OBM_RATE_ARCHIVE_TODAY_MS=60000`, and `OBM_RATE_DEFAULT_MS`), different hosts run in parallel, and the expected time is printed first. An HTTP 429 or 503 is retried after its Retry-After (seconds or an HTTP-date), else an exponential backoff with jitter (60 s, doubling, at most 10 min), and that host is slowed by 1.5x for the rest of the run; a URL is given up after 5 tries (`OBM_RATE_MAX_TRIES`) or when the run's 60 min budget (`OBM_RATE_BUDGET_MS`) would be passed, and logged `rate-limited (gave up after K tries over T; ...)`. A challenge or CAPTCHA (an archive.today or Ghostarchive 403, a Cloudflare `cf-mitigated: challenge` header, or a CAPTCHA page, checked with one GET after a host's first 429/503) is not retried and is logged `blocked (challenge/CAPTCHA; ...)`; in audit these read `no verdict` with detail `HTTP 429 (rate-limited: gave up after K tries over T)` or `HTTP 429 (blocked: challenge/CAPTCHA)`. Every URL must get a verdict: verify exits 3 (incomplete) when it has no findings but some URL is still rate-limited, blocked or unconfirmed, and prints a `verify: INCOMPLETE:` line; audit prints an `audit: INCOMPLETE:` line when links are left rate-limited or blocked, and still exits 0. Any other failure is a finding and exits 1 (see Exit codes below); a dead snapshot (HTTP 404 or 410) is excused only by a `- Re-archive: <new archive URL>` line added to the same extract in the same diff (it names the new capture, which verify checks too), and a redirect is followed only to the same capture (at most 5 hops). The rules it applies are the network half of L8 below.

`bun run audit` is a local script, never in CI and never a merge gate. It re-checks every Original URL, Archive URL, Archive URL 2 and Archive URL 3 in the repository by HTTP status and content, and classifies each as ok (resolves, and its sha256 matches the last saved copy; on a first run any resolving URL is ok), changed (resolves, but its content differs from the last saved copy, or it redirects to a different final URL than last time), lost (404, 410, or the host name does not exist, DNS ENOTFOUND, while a canary host, `www.gstatic.com` or `one.one.one.one`, still answers), or no verdict (403, 429, blocked; Ghostarchive also 503, its Cloudflare challenge, and a 200 that is not a capture, its `Archiving error` page or a loading page, which is not saved; a Ghostarchive 429 is no verdict, the same as archive.today's; any other DNS error, such as the resolver timing out; and every transport failure when no canary answers, since then the network itself is down). The script does not judge whether a figure is still shown. Wayback captures are fetched raw (`https://web.archive.org/web/<timestamp>id_/<url>`) for hashing; originals are hashed as served, so a dynamic original may show as changed and needs a human look. It saves whatever still resolves, with a `manifest.json` of each URL's sha256 and final URL and dated reports `reports/audit-<YYYY-MM-DD>.md` and `.json`, to a local store outside the repository (default `~/open-inflation-archive/`, or `$OBM_ARCHIVE_DIR`; a store inside the repository, symlinks resolved, is refused). Those copies are private, never committed or published. Requests are paced per host as for verify (hosts in parallel; archive.today 30 s apart), with a timeout and a User-Agent. Findings are appended to the quarter's research log, `research/base_money/<YYYY>Q<n>.md`, under `## Link audit <YYYY-MM-DD>`.

Exit codes, the same for every script: `0` clean, `1` findings, `2` usage or error (a bad argument, a base that cannot be resolved, not a git checkout, a refused store, or any uncaught internal error, which never exits 1), `3` incomplete (no findings, but some URL got no verdict). lint uses 0, 1 and 2; verify uses all four; audit uses 0 and 2: its results, including lost, changed and no verdict, are a report for the researcher, not findings.

Code checks: `bun run typecheck` and `bun run check` (format and code lint).

CI: `.github/workflows/lint.yml` runs `bun test`, the code checks and `bun run lint` on every push and pull request, with no network step; it never runs `verify` or `audit`.

## Versions

Each series in `catalog.json` carries a semver `version` (base_money: `0.1.0` for the skeleton, `1.0.0` from its first published row, basket v1). The series' `baskets` list every basket of issuers ever used, versions 1..n, each with its coverage `floor_pct`; a committed basket entry is immutable as a whole (its issuers, their order and its `floor_pct`) and is never edited or removed. A basket change appends a new basket, with a major version bump plus a git tag. One CSV may hold rows computed under different baskets: each row keeps the basket in force when its quarter was first published, unless an appended Revision adds a newly evidenced issuer, which moves the row to the newer basket. The basket is recorded in the roll-up's machine block as `basket_version` (implied 1 while only one basket exists) and named per quarter in `INDEX.md`, which warns that rows on different baskets are not strictly comparable.
