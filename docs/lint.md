# What lint enforces

`bun run lint` runs every check below on the working tree against a base commit (see [running the checks](running.md#lint)). It makes no network calls, ever.

## Checks

### L1

`base_money.csv` is UTF-8 with no byte-order mark, LF line endings and a final newline; header exactly `date,value,evidence_id`; quarter-end ISO dates, strictly ascending; non-negative integer USD values.

### L2

Every `evidence_id` is `evidence/base_money/YYYYQn.md`, exists, and matches the row's quarter.

### L3

No committed heading in `issuers/` or `evidence/` is renamed or removed.

### L4

Committed basket entries in `catalog.json` are never changed or removed (append a new version instead). Committed lines in `issuers/` and `evidence/` are never changed or deleted. Committed CSV rows are never deleted; a value changes only if the same diff appends a `## Revision` section with a new full machine block to that roll-up whose `total_usd` is the new value (an append, so no exception to the rule above).

### L5

Every relative link and anchor in `README.md`, `docs/evidence-index.md`, the roll-ups and their machine blocks (component and `reference_values` anchors) resolves; anchors are GitHub's lowercase slugs (`## 2026Q3` is `#2026q3`); an issuer-year file has at most one `## YYYYQn` heading per quarter.

### L6

`docs/evidence-index.md` links every roll-up and every issuer-year file, and once `README.md` carries its generated blocks, its table links every roll-up.

### L7

Every extract has `- Retrieved:` (UTC, not later than now plus 10 minutes), `- Original URL:`, `- Archive URL:` (a web.archive.org snapshot of that page taken within 24h; the two URLs are compared percent-decoded per component, since Wayback writes `/` in a query as `%2F`, and a malformed `%` escape fails), exactly one `- Archive URL 2:` (an archive.today capture, `https://archive.ph/<id>`, `https://archive.today/<id>` or `https://archive.is/<id>`, or the dated form `https://<same hosts>/<YYYYMMDDhhmmss>/<Original URL>` with a real timestamp and that Original URL; or, when no capture could be made, `attempted <YYYY-MM-DD>: <reason>` with a real date and a reason of at least 3 words (a word counts only if it contains a letter or a digit) containing no URL, no `scheme://` (any scheme, any case), no `www.` and no bare host or path such as `example.com` or `archive.ph/abc`, no IP address such as `1.2.3.4`, and no malformed URL, a host joined to anything by `/`, `:`, `@` or `\` such as `x/example.com`, `https:example.com`, `http//example.com` or `localhost:8080` (archive.today's own names, `archive.today`, `archive.ph` and `archive.is`, may appear as words; abbreviations such as `U.S.` and file names such as `data.xlsx` are not hosts); the attempt date, and the UTC date of the dated form's timestamp, must be on or after the UTC date of Retrieved (archive.today is tried at or after retrieval) and not after the UTC date of now plus the same 10 min skew; any other host, a self-hosted copy included, fails), exactly one `- Archive URL 3:` (a Ghostarchive capture, `https://ghostarchive.org/archive/<id>` with the id letters and digits only and nothing after it, no query, fragment or trailing path, and no timestamp check; or `attempted <YYYY-MM-DD>: <reason>` under exactly Archive URL 2's date and reason rules; `http://` and any other host fail) and a verbatim quote; `- As of:` (the observation date) is `YYYY-MM-DD` or `YYYY-MM` (a real date), optionally followed by one parenthetical note to the end of the line, and under a `## YYYYQn` heading falls inside that quarter (a month is in it if the month is); an issuer with `as_of_convention: "start_of_day"` in the catalog must use exactly the first day of the next quarter (its start-of-day stock is the quarter-end stock; no other date passes); As of (a `YYYY-MM` As of counts as that month's last day) is not after the UTC date of `- Retrieved:`; FX extracts need a full `YYYY-MM-DD` from quarter-end minus 3 days to quarter-end, and each FX extract (`issuers/FX/<YYYY>.md`) has exactly one each of `- Currency:` (ISO code), `- Quote as published:`, `- Quote direction:` (`<CCY> per USD` or `USD per <CCY>`, naming its own Currency), `- Rate:` (a normalized copy of the quote: a positive plain decimal `^\d+(\.\d+)?$`, the same digits with a decimal comma as a point, so the CBR "77,7539" is `77.7539`; quotes with digit grouping are unsupported, and a quote with a single separator is confirmed in review) and `- fx_rate (USD per unit):`, which equals the rate derived from Rate and direction (Rate itself for USD per unit; 1 / Rate rounded half-to-even to exactly 20 decimal places for units per USD; exact string match); a field written in another form fails as the wrong form.

### L8

Lint makes no network calls: it checks form only (the archive URLs themselves under L7, and each `- Re-archive:` note sits in an extract, is not one of that extract's own archive URLs, and names a Wayback snapshot `https://web.archive.org/web/<14 digits>/<url>`, an archive.today capture URL or a Ghostarchive capture URL). The link check moved to `bun run verify`, a local research script, not a merge gate, which applies these rules to each archive URL the diff adds: each newly added archive URL answers a HEAD request. Redirects are followed only to the same capture timestamp (another scheme, host or `id_`-style modifier); a redirect to another timestamp fails (the recorded snapshot does not exist; Wayback sent its nearest capture), as does one off the snapshot or more than 5 hops; if web.archive.org is unreachable, archive.org's availability API returning exactly the recorded snapshot timestamp passes (asked in up to three equivalent query forms; `ok (archive.org availability, <timestamp>, query form N)` names a form after the first), and any other answer (no snapshot listed, another capture, an HTTP or network error) is logged `unconfirmed (web.archive.org unreachable (...); archive.org availability: ...; no verdict)`, not a failure (the capture itself was never seen; exit 3). A Wayback HTTP 429 still there after the pacing retries is logged `rate-limited (...; web.archive.org HTTP 429; no verdict)`, not a failure. Progress for each URL goes to stderr: `ok (HTTP 200, <timestamp>)`, `ok (archive.org availability, <timestamp>)`, `excused (HTTP 404, Re-archive note)`, `unconfirmed (...)`, `offline (...)` or `fail`. A `- Re-archive: <new archive URL>` line added to an extract in the same commit names the new capture (verified like any new archive URL, even when the same URL is already committed elsewhere) and excuses only a confirmed dead snapshot (HTTP 404 or 410) of that extract. A new archive.today URL (`Archive URL 2`) gets one HEAD; redirects are followed only between archive.today hosts (at most 5 hops); HTTP 403 or 429 (its CAPTCHA or rate limit) is logged `blocked (challenge/CAPTCHA; archive.ph HTTP 403; no verdict)` or `rate-limited (archive.ph HTTP 429; no verdict)` (the host as written) and does not fail; any other HTTP error, a redirect off archive.today or a network error while a canary host answers fails, with no availability fallback (with no canary answering, a network error is `offline (...; no verdict)`). When any new archive.today URL was verified or rate-limited, verify ends with the stdout line `archive.today (distinct URLs): N verified, M unverified (R rate-limited, B blocked)` (M = R + B, plus `, U unconfirmed` and `, O offline` when not 0) followed by each unverified URL, one per line, sorted, for the researcher to open by hand while archiving (not in PR review) (failures are findings and not counted; no line when N + M is 0). A new Ghostarchive URL (`Archive URL 3`) gets one GET, reading at most 256 KiB of the page; redirects are followed only to another `ghostarchive.org/archive/` URL (at most 5 hops); HTTP 403 (its Cloudflare challenge) is logged `blocked (challenge/CAPTCHA; ghostarchive.org HTTP 403, Cloudflare challenge; no verdict)`, and HTTP 429 or 503 is retried as a rate limit and, still there at the cap, logged `rate-limited (gave up after K tries over T; ghostarchive.org HTTP 503, rate limit; no verdict)` (blocked instead when a challenge page or header is detected), and neither fails; an HTTP 200 passes only when the page is a capture: Ghostarchive's `Archiving error` page fails (record an attempt instead; a Re-archive note does not excuse it) and any other 200 page is `unconfirmed (ghostarchive.org HTTP 200, no capture on the page (loading, in progress or unrecognised); no verdict)`; any other HTTP error, a redirect off Ghostarchive or a network error while a canary host answers fails (with none answering, `offline`, no verdict), a 404 or 410 excused only by a Re-archive note; verify then prints `ghostarchive (distinct URLs): N verified, M unverified (R rate-limited, B blocked[, U unconfirmed][, O offline])` and the unverified URLs, sorted (no line when N + M is 0); requests are paced and retried (see `bun run verify` above).

### L9

Each roll-up has one or more fenced `yaml` machine blocks (no front-matter), one per vintage; a revision appends a `## Revision <date>` section with a new full block and never edits an earlier one; every block is validated on its own; each component's and each reference value's USD is `local_value` × `fx_rate`, computed exactly and rounded half-to-even to a whole dollar, and `total_usd` is the sum of those whole dollars; a USD `local_value` with a decimal point (more precise than $1, `1000.0` included) fails, and a `local_value` in any currency is exact with no leading zero (`0123` and `00.5` fail; a plain `0` and `0.5` are allowed); the last block is current, and the CSV value must equal its `total_usd`; each component anchor is `issuers/<its issuer>/<year>.md#<quarter slug>`; `exclusions` entries are `{issuer, reason}`, both required, and components + exclusions list every issuer of the block's basket exactly once (never in both, never an issuer outside the basket); every non-USD component currency has an FX extract (`- Currency: <ISO>`) under the quarter's heading in `issuers/FX/<YYYY>.md`; every `fx_rate` in `components` and `reference_values` is `"1"` for USD and otherwise equals, as a string, the rate derived from the one adopted FX extract (`- Adopted: yes`) for that currency under the quarter's heading (no adopted extract, more than one, or an adopted extract that fails L7 fails); `basket_version` (a positive integer naming a catalog basket, written plainly: `1`, not `"1"`, `1.0`, `1e0`, `0x1`, `01`, `+1` or `!!int 1`) is optional while the catalog lists one basket (absent means 1) and required on every newly appended block once it lists more; the block is checked against its own basket; `reference_values` (`{issuer, anchor, local_currency, local_value, fx_rate}`, exactly one per excluded issuer, also needing FX extracts, never counted in `total_usd`) and `coverage_pct` (a string with exactly 2 decimals) are required in every block: coverage = Σ components ÷ (Σ components + Σ references) × 100 over those whole-dollar figures, rounded once half-to-even to 2 decimals, must match; the exact coverage of the whole-dollar figures (the ratio itself unrounded) must be at least the basket's `floor_pct` (a true floor: 93.995 fails a 94 floor though it rounds to 94.00); optional `cross_checks` name another published aggregate (name and url only, never a figure).

### L10

Every file is UTF-8 text with no byte-order mark and at most 1 MB.

### L11

`catalog.json` matches its schema (it lists a `base_money` series; each series has a semver `version`, a known data `license` `baskets` `[{version, issuers, floor_pct}]` with versions 1..n in order, non-empty unique upper-case issuers and a floor from 0 to 100 with at most 2 decimals, and an optional `issuers` list of `{id, as_of_convention?}` with unique ids from the baskets and `as_of_convention` only `"start_of_day"`; appending a basket bumps the major `version`; against the base, `version` never goes down, compared by semver precedence (1.0.0 to 0.1.0 fails, an equal or higher version passes, build metadata is ignored)) and points at files that exist.

### L12

Issuer files live only at `issuers/<ISS>/<YYYY>.md` with `<ISS>` an upper-case id in any catalog basket version, or exactly `FX` (`issuers/FX/` holds FX-rate sources); roll-ups only at `evidence/base_money/YYYYQn.md`; research logs only at `research/base_money/YYYYQn.md`; all patterns are exact and case-sensitive; any other file under `issuers/`, `evidence/` or `research/` (any extension, or none) fails, except `.gitkeep`.

### L13

`README.md`'s generated blocks (`latest`, `table` and `yoy-notes`, between their `<!-- BEGIN GENERATED ... -->` and `<!-- END GENERATED ... -->` markers) and the whole of `docs/evidence-index.md` equal what `bun run readme` writes from `base_money.csv`, each roll-up's last machine block and `catalog.json`: the value in trillions (half-to-even, 2 dp), YoY per the rule below, coverage, the excluded issuers, the catalog version and update date. A hand-edited number, a removed marker or a stale index fails; the fix is `bun run readme`. The check is skipped only while an input cannot be read, which L1, L2, L9 or L11 report. YoY is (value / value four quarters earlier − 1) × 100, exact, half-to-even to 1 dp, always signed (`+3.2%`, `-1.4%`, `0.0%`), shown only when that earlier quarter is in the CSV and has the same basket version and the same included issuers; otherwise `—¹` (no year-ago quarter) or `—²` (basket or coverage change), `¹` taking precedence.
